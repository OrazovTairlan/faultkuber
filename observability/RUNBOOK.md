# Alert runbook

Rules are defined in `observability/alerts.json` and evaluated by `scripts/obs.py` (AlertEngine).

| Alert | Severity | What it detects | Threshold | Expected response |
|---|---|---|---|---|
| HighErrorRate | critical | User-visible failures: share of gateway responses with a 5xx status. | 5xx / all gateway responses > 5 % over 5 s, with at least 20 requests in the window | Page on-call. Check which upstream is failing (ReplicaUnavailable, DatabaseUnavailable), follow the matching runbook; if a release caused it, roll back. |
| HighLatencyP95 | warning | Slow service: gateway p95 latency approaching the 500 ms requirement (load spike, slow dependency). | p95 of gateway latency > 300 ms over 10 s, at least 20 requests | Check load and CPU throttling; scale the gateway/services out or shed load (rate limits stay on). Investigate slow dependencies. |
| ReplicaUnavailable | warning | Lost redundancy: a Deployment or StatefulSet has fewer Ready pods than designed. | ready pods < desired (gateway 2, auth 2, course 2, registration 2, db 2) for 1 s | Kubernetes restarts the pod automatically. If not back within 60 s, page on-call; check events and the node. |
| DatabaseUnavailable | critical | Registration cannot reach any database node (blocked network, both nodes down, circuit open). | >= 3 'db_unavailable' events in registration within 10 s | System: registration answers 503 + Retry-After and stays up. Team: run the data-tier runbook, check db pods and NetworkPolicies, restore from the vault only if data is damaged. |
| DegradedMode | warning | A non-critical feature is served from the stale cache because the Course service is unreachable. | >= 1 'degraded_response' at the gateway within 10 s | System: stale data is served with an X-Degraded header. Team: restore the Course service; data older than 10 minutes is no longer served. |
| BruteForceLogin | critical | Password guessing: repeated failed logins. | >= 5 failed logins (auth) within 30 s (the account lockout threshold) | System: accounts lock for 30 s after 5 failures. Team: identify the source in the audit log, block it at the edge, notify the account owner. |
| UnauthorizedAccessSpike | critical | Requests without valid credentials: missing, forged or expired tokens. | >= 5 'unauthorized_request' events at the gateway within 30 s | System: request denied and audited. Team: review audit events by subject and source, revoke the token or lock the account if misuse is confirmed. |
| ForbiddenAccessSpike | critical | An authenticated user repeatedly tries to read or change data of another user (broken-authorization probing). | >= 3 'forbidden_access' events within 30 s | System: 403 returned and audited. Team: inspect the subject in the audit log; lock the account if the pattern continues. |
| RateLimiting | warning | A client exceeds its request budget (abuse or a misbehaving client). | >= 20 'rate_limited' events at the gateway within 10 s | System: excess requests get 429 + Retry-After. Team: identify the client; raise the limit only for a verified legitimate client. |
| MalformedRequestBurst | warning | Fuzzing or a broken client: many requests rejected by input validation. | >= 10 'validation_rejected' events (gateway + registration) within 30 s | System: 400/413 returned, nothing stored. Team: check the source and the client version in the access log. |
